# Dataset Documentation: Internally Curated & Synthetic Email Benchmark

## 1. Overview & Provenance Disclosure
This dataset contains **341 email records** categorized into **PHISHING** and **SAFE** classes, developed specifically for training, benchmarking, and evaluating machine learning classifiers within the PhishGuard AI application.

> [!IMPORTANT]
> **Dataset Provenance Notice:**  
> This dataset is **entirely internally authored and synthetically generated**. It does **not** contain raw records imported or downloaded from external public archives such as SpamAssassin, the Jose Nazario Phishing Corpus, or the Enron Email Dataset. While the email templates were designed to reflect common attack modalities and legitimate corporate communication styles, every record was created programmatically within `data/download_dataset.py`.

The 341 unique records in `data/emails.csv` are composed of two distinct components:

| Component | Record Count | Percentage | Description |

| **Synthetically Generated Variations** | **261** | **76.54%** | Parameterized variations (138 Phishing, 123 Safe) generated by cycling institutions, brands, amounts, case IDs, department names, and URL structures through structured text templates. |

## 5. Duplicate-Aware Splitting & Evaluation Methodology

Because 76.5% of the dataset consists of template-generated variations, conventional random stratified train/test splitting leads to **data leakage** (where different variations of the same template appear in both training and test sets).

To ensure scientific validity and prevent memorization:
1. **Template Fingerprinting:** Each email subject is normalized into a canonical `template_group` key by masking numbers, currency values, and case IDs.
2. **Group-Based Splitting:** The dataset is split using **`StratifiedGroupKFold`**, guaranteeing **zero group overlap** between training and testing sets.
3. **Generalization Testing:** Test samples evaluate whether the model has learned general linguistic and structural features (e.g. urgency cues, credential harvesting keywords, IP hosts, suspicious TLDs) rather than memorized template text.

---

## 6. Known Limitations of This Dataset

1. **Synthetic Nature:** Because 76.5% of samples were generated via templated loops, vocabulary distribution is more constrained than organic enterprise mail streams.
2. **Mock URLs:** All embedded hyperlinks use non-resolving mock domains, defensive test links, or numerical IP examples.
3. **Sample Size:** 341 records provide a compact benchmark for testing pipelines and demonstrating ML concepts, but large-scale enterprise deployments require evaluation against larger real-world corpora.
4. **Adversarial Drift:** Advanced obfuscation techniques (such as homoglyph attacks, zero-font injection, or dynamic cloaking) are not fully captured in static template variations.
